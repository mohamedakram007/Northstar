# Northstar

**Plan with purpose. Execute with discipline.**

Northstar is a personal growth and performance workspace with a Vite frontend and an Express/MongoDB backend. It includes a dashboard, daily planner, habits, career goals, learning, projects, job applications, calendar, fitness, reading, knowledge hub, reports, and settings.

## Features

- Calendar events, fitness workouts and body measurements, books and reading sessions, searchable knowledge notes, and date-range reports with CSV export and print.
- Existing planning, habit, career, learning, project, and job application workflows.
- Local-first browser storage, downloadable JSON backups, and merge import.
- Optional account sign-in with password hashing, rate-limited authentication, secure HTTP-only session cookies, and per-account MongoDB records.
- Manual sync merges records by stable record ID. Browser data remains available offline and is retained after sync.

## Run locally

Requirements: Node.js 20+, npm, and MongoDB (local MongoDB or an Atlas connection string).

1. Copy `.env.example` to `.env`; set `MONGODB_URI` and a random `JWT_SECRET` of at least 32 characters.
2. Install and start the API: `npm install`, then `npm start`.
3. In another terminal run `npm run dev`, then open the URL Vite prints. Vite proxies `/api` to port 4000.

The server serves the built frontend in production. Use `npm test` for calculation tests and `npm run build` to create the production frontend.

## MongoDB Atlas, Compass, and Render

1. Create a MongoDB Atlas cluster and a database user. Copy the application's connection string, replacing the password placeholder and adding `/northstar` as the database name. Keep this string private.
2. In MongoDB Compass choose **New Connection**, paste the same Atlas connection string, and connect. The app creates `users` and `records` collections on first account/data use.
3. Create a Render **Web Service** from the GitHub repository. Render detects `render.yaml`; set `MONGODB_URI` in the service environment to the Atlas URI. `JWT_SECRET` is generated by the blueprint. Deploy. Render's health check is `/api/health`.
4. In Atlas Network Access, allow the Render service's outbound IP addresses. If those are not fixed for the selected Render plan, use Atlas' broader IP access only with a strong database password and review the exposure tradeoff.
5. Open the Render URL, go to **Settings**, create an account, then choose **Sync this device**. Existing browser records are merged into MongoDB.

### Store development data on this Windows PC

Install and start MongoDB Community Server locally; Compass by itself is only a database viewer/client and does not run the database server. Set `MONGODB_URI=mongodb://127.0.0.1:27017/northstar` in `.env`, start Northstar's API, then open Compass and connect to `mongodb://127.0.0.1:27017`. Northstar stores its local database on this PC through the MongoDB server's configured data directory. The local connection works for development on this PC. Render cannot reach `127.0.0.1` on your PC, so the live service needs an Atlas connection string; Compass can also connect to that same Atlas database.

Never put database credentials in frontend code, Git, or a public issue. MongoDB Compass is a database client; Atlas hosts the online database and Render runs the app/API.

## Data and security notes

- MongoDB records are scoped to the authenticated account. Passwords are hashed with bcrypt; session tokens are held in HTTP-only, same-site cookies.
- Manual sync merges by record ID and local records win when IDs conflict. Sync does not delete remote records.
- Use Settings to download a JSON backup before changing browsers or accounts.
- This is a personal-use application. Add account recovery, email verification, automated backups, and a formal privacy policy before offering it as a public multi-user service.
